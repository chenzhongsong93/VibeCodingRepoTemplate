# v2测试设计

因子：schema/能力/风险T0–T3、profile/intent、栈/无栈、中文/自定义路径、runtime/角色、文件owner/已有文件/symlink、工具存在/非零/超时、ID层级/多重性/selector、任务阶段/审批引用/证据新鲜度、升级基线/人工变更/中途变化。

边界：空/未知配置；stage非法/空节；一个/两个冲突输出；空测试集合与重复ID；无L2/L3检查；无/旧/新证据；文件存在/缺失/被改；两个独立任务；本机/共享快照。

异常：工具缺失/失败/超时、JSON坏输入、越界/符号链接、旧任务状态覆盖、升级冲突。验证使用临时样本和本地Node子进程，不需要服务、网络或Git提交。

| 用例族（函数名/测试名带ID） | 验收 | 分支 |
|---|---|---|
| ASM-* | AC01/02/04/11/14 | 规范化/互斥/owner/路径/新仓冲突 |
| CHK-* | AC03/05/06/09/12/13 | 合法/缺失/非法/空/重复/错误 |
| RUN-* | AC04/05/08/12/15 | repo/subset/complete、fail/blocked/skipped/N/A |
| TASK-* | AC07/08/09/15 | create/advance/done/冲突/过期/恢复 |
| UPG-* | AC10 | plan/check/apply/手改/途中变/版本/备份 |
| PLAT-* | AC04/11/12 | 本地入口/权限薄适配/外置hook/只读预览/多仓 |

L1：函数和检查器反例；L2：真实生成文件+Node CLI/本地命令+文件升级集成；真实平台/部署L3仅在相应环境可用时验证，不在本机假造。既有v1测试仍独立运行。
