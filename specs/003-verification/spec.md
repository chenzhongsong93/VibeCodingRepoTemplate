# 验证与证据 — 长期特性功能设计

> 域：003-verification。目标：已接受。实现：来源/完成保护、资产与证据保护、存量接入及运行集成已通过分项本地验证与独立审阅。

## 目标与非目标

为规范/设计及行为提供范围明确的证据，防止失败、跳过、错误输入或工具计数冒充完成。支撑开发治理，不以状态机、hash或注册条目定义目标，不建设安全隔离/批准签名系统。

## 约束与上下文

遵守[系统SYS-I3/I4/I6](../../docs/00-system/system-design.md)。输入是项目本地检查、正式系统/域/契约/测试资产和当前变更；输出分机器结构、行为、真实环境、语义审查及未完成状态。工程目标来自002；文件/路径运输来自001。

## 结构与关键流程

runner计算适用检查、调用本地命令及builtin、记录退出/版本/输入指纹与本地证据；checks处理基础结构/路径/完整性/追溯；trace为受限词法辅助。Make/npm/hook只包装同一入口，安装/执行/通过分别报告。

runner通过storeRunReport登记受管run并返回assetId/evidencePath；失败独立运行pin待分诊，任务运行active-pin。finish先核验最新结果/输入/验收并保护证据，再更新任务状态，最后释放旧run的任务pin；释放失败保留保护并报告maintenanceWarning。`./`等证据路径别名归一化，不能绕过最新凭据保护。证据的local-only/local-copy及实际传递分别报告，缺失/过期不能靠旧摘要冒充当前可核验。

consumedInputs绑定实际配置、交接、设计及传递Markdown依赖、本地argv执行文件和check.inputs。导航目录链接只绑定目录身份/类型；显式递归目录输入绑定内容，含harness保留输出根的目录输入拒绝，避免自我失效。可选task助手和runner共享completionChecks，必需core.assets检查策略/登记/journal元数据而不运行GC。

整体复审F1/F2的补强契约（已实现并通过最终验证/限定复审）：默认Python检查以`inputSelection: {kind: "python-files", excludeDirectoryNames, excludePaths}`枚举cwd下实际`.py/.pyi`文件；目录名及cwd相对路径的排除清单公开，实际argv添加`--`及选中文件，`fingerprintScope.commandSelections`记录规则、cwd及文件集合。consumedInputs直接绑定选中集合及各文件内容，不依赖argv启发式；`--`后的负号前缀文件/目录也按位置输入绑定；空选择不能当通过，文件内容/成员变化使旧凭据失效。自定义递归输入不被暗中裁剪，避免用默认策略悄悄改写用户命令。

受管输入须在冻结/执行前于协作锁内解析资产身份并取得租约；报告持久化时将保护转为run→input引用，之后才释放租约。完成/失败凭据及保留期内普通run的保护传递到必要输入；noRecord在结束后释放，落盘失败/进程中断保持可盘点租约供明确恢复。报告退休且没有其他保护后，输入仍按自身关闭/保留策略决定回收。只消费已登记对象，未知历史不因此被认领。

设计检查从实际Markdown权威和连续样本提炼：域未注册/重复正文/缺结构/过程材料跟踪可机械发现；系统职责/图方向/验收充分性与目标偏差交给真实语义审读。最小机查拒绝空设计节、未定义/重复验收ID、缺适用专门owner及被管理的过程稿；ID词法存在不证明测试覆盖语义。可选task助手完成前须有域来源和收敛审查，不能凭阶段note或验收指向core.policy结束。

### 已修复的专项审核缺口

- C01：验收来源仅可为声明的当前权威，忽略草稿/任务自引用拒绝；finish重验来源内容与实际消费输入闭包。
- C02：impact.paths中明确命中的注册域/公共/专门owner纳入收敛，域索引允许任意已声明的本地Markdown正文路径。
- C03：空宪法、仅标题/占位系统设计不能完整结束；初始化骨架可生成，不等于完成底座有效。
- C05：非阻断遗留必须有可验证的共享转交path/id/closureCriteria及交接指针，完成保留下一步。
- C08：测试标签关联实际声明/selector并处理参数化；字符串中的括号不当语法，映射仍不能证明语义覆盖。
- C09：显式“历史证据/历史溯源”链接可保留出处，不能被选作当前验收权威。

以上均有反例/合法对照和分项审阅；C04归002，C06/C07归001。旧156项测试绿却遗漏这些问题的教训仍适用，新增测试和审阅只证明所覆盖范围；无task助手的内容审查不能以N/A冒充完成。

### 后续项目验证与效果评价

结构完整、来源hash、自填审查结论和实际语义正确是不同主张。本轮静态复核与行业研究支持把后续验证分为架构依赖、契约兼容、跨域业务不变量、运行环境和真实内容审阅；每层声明可检出范围，不用某层通过替代其他层。C01–C09已转为修复回归；架构/业务项目约束仍须按实际项目接入。

- 来源及证据：绑定实际消费输入、工具/命令/cwd和环境；未提交内容不能只用HEAD标识。来源存在不证明有权批准，输入闭包不全时hash不能保证新鲜度。
- 架构与契约：按项目现有栈执行依赖/循环/边界测试、契约再生及消费者/提供者验证；配关键业务状态/故障场景。静态依赖合法、schema兼容分别不证明动态行为和业务语义正确。
- 成熟仓：可评审存量违约基线、防新增并逐步偿还；不得重录基线造绿，关键安全/业务阻断不能因存量而豁免。可参考[ArchUnit §8.6](https://www.archunit.org/userguide/html/000_Index.html)，不把Java工具设为通用依赖。[Pact FAQ](https://docs.pact.io/faq)明确契约测试的功能/性能边界。
- 门禁充分性：每条候选约束配能触发的坏例及应通过的合法对照；用真实缺陷校准语义审阅者，不能把多Agent同意当独立实证。
- 资产维护：新增关闭/引用/保留条件、计划失效、隔离恢复、并发生产者、时钟异常、旧资产认领和周期执行反例；检查清理后活设计/必要证据/续接仍成立。完成保护已补C01/C02/C03/C05回归，仍不能只以done状态作为删除依据；正文内容与资产生命周期检查各守边界。
- 试点归因：以已修复C01–C09的版本作为基线，再比较现方案与候选方案；固定模型/工具/任务/输入/质量约束，模型升级另作比较。建议从不同形态的两个真实项目域、各8–12次连续变化起步；仅为试点规模建议，不是统计充分性承诺。
- 评价指标：关键违约检出及合法误阻断、当前来源定位、设计漂移持续时间、无本地稿恢复、总耗时/token/人工修复成本，以及活跃知识的重复/冲突与新增架构债务。各自明确分母，计入失败/超时/人工救援；不以文档行数或测试数代替效果。

本轮尚未执行上述长期试点。只有在固定验收下实际比较后，才能判断候选机制是否提升Agent维护质量；不能将方法文档、厂商经验或短期样本成功提升为规模化效果证明。
