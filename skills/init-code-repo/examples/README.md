# 持续设计治理的填实样本

`governed-project/`是纯本地作业队列，提交和执行两个域共用一份系统/数据契约。它是供阅读和隔离试用的成品，不会被装配器强塞进新项目。

在独立临时目录先用minimal配置装配骨架，再复制本样本内容到该目录；不要覆盖已有业务仓。进入样本根目录运行`node --test tests/*.test.mjs`查看基线行为。Node>=22，无数据库、服务或新增依赖。

阅读顺序：生成的AGENTS/e2e→本样本系统设计→域索引→两个spec→src和测试。新增重复策略、输入约束或取消语义时修订同一spec；公共变更同时修改共享owner及受影响域，保留批准目标/实现状态和决策取代关系，执行细稿放忽略区。

维护仓`tests/v2/evolution.test.mjs`复用这一份样本，真实跑同域三轮RED→GREEN、跨域取消缺陷与独立共享快照，最终同域仍只有一份设计。该测试是验收场景，不是生成项目运行所需依赖。Spec Kit实际调用和不同OS/Agent加载需在有相应工具的环境另行验证。
