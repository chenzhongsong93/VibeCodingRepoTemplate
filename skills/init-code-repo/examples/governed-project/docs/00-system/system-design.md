# 本地作业队列 — 系统总体设计

> 目标：样本验收基线v1。实现：初始纯函数已实现；后续演进逐项标记，不能从目标推断已交付。

## 目标与非目标

客户端提交带唯一ID的作业，执行域消费排队作业。只使用调用方提供的内存Map和执行函数，不提供HTTP、数据库、集群调度或后台服务。

## 边界和使用场景

提交域负责输入合法性、创建及重复提交语义；执行域负责开始、成功/失败回报和不可重复运行。共享记录字段只有[数据与契约](domain-model.md)一个owner，域设计只引用。

## 公共不变量

- SYS-I1：只有queued作业可以开始；终态不能重新开始，用户可见状态与实际副作用一致。
- SYS-I2：同一ID只有一条作业，重复提交策略由提交域定义；执行不能重建提交记录。
- SYS-I3：域间共享字段/状态的变化同时对照两个域，不能只改入口或复制字段定义。

## 结构与关键流程

`src/submit.mjs`创建记录，`src/execute.mjs`消费；失败由执行域设置failed并重新抛出原错误。两域都是同步控制面与异步执行函数的组合，Map保存当前事实。

## 质量、部署与验证

Node本地模块，无服务/网络/持久化。断言创建、重复、不可重复运行及异常状态；跨域新语义必须有独立断言，不用旧正例绿替代。
