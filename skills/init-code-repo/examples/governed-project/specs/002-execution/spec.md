# 执行域 — 长期特性功能设计

> 域：002-execution。设计版本：v1。目标：已接受。实现：初始样本已支持排队状态校验与结果回报。

## 目标与非目标

消费已有作业，维护执行副作用与可见状态一致；不负责提交/去重。依赖[系统SYS-I1/I3](../../docs/00-system/system-design.md)和[共享契约](../../docs/00-system/domain-model.md)。

## 约束与上下文

输入Map、ID、异步执行函数；只有queued可启动。结构位于`src/execute.mjs`，不得另建提交记录。

## 需求与验收

- EXE-R1：Given queued，When执行成功，Then只执行一次并记done和result。状态：已实现。
- EXE-R2：Given不存在或非queued，When执行，Then拒绝且不调用执行函数。状态：已实现。
- EXE-R3：Given执行函数失败，Then记failed与error并抛出原错误。状态：已实现。

## 架构与关键流程

读记录→校验可开始→标running→await执行→成功/失败回报。任何新共享状态或取消规则都必须在真正副作用前校验，不能只改提交入口。

## 数据与运行

公共结构只引用共享契约；本域仅写执行结果。纯Node，无后台调度和部署依赖。

- 专门权威（测试）：[提交与执行长期回归](../../docs/02-design/test-spec/submission.md)
