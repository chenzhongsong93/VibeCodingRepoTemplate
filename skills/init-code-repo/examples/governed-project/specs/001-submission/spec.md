# 提交域 — 长期特性功能设计

> 域：001-submission。设计版本：v1。目标：已接受。实现：下列验收已由初始样本支持。

## 目标与非目标

为作业建立唯一身份和排队记录，不负责执行或公共记录字段定义。遵守[系统SYS-I2](../../docs/00-system/system-design.md)，共享结构只引用[数据契约](../../docs/00-system/domain-model.md)。

## 约束与上下文

输入为Map、ID和payload，输出为该ID的记录；唯一实现`src/submit.mjs`。现有ID重复提交抛出duplicate，不创建第二条记录。

## 需求与验收

- SUB-R1：Given新ID，When提交，Then仅新增一条queued记录并返回该记录。状态：已实现。
- SUB-R2：Given已有ID，When再次提交，Then抛出duplicate且原记录不变。状态：已实现。
- SUB-R3：Given空ID，When提交，Then失败且Map不变。状态：已实现；后续更严格输入类型需单独批准。

## 架构与关键流程

先验ID→查重复→创建→返回；失败不得部分改变Map。重复策略属于本域，执行域不能擅自改变。

## 数据与运行

字段/状态见共享数据契约，不复制定义。纯Node模块，不需要服务或迁移。

- 专门权威（测试）：[提交与执行长期回归](../../docs/02-design/test-spec/submission.md)

## 红线

不按一次变更新建另一份提交设计，不绕过身份唯一性，不把计划中的幂等行为写成已验证。
